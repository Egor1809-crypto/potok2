# Telegram: подключение и подписки

В «Каналах и интеграциях» участник подключает отдельного Telegram-бота токеном из BotFather. Поток проверяет `getMe`, устанавливает защищённый webhook и выдаёт ссылку `https://t.me/<username>?start=potok`. Подключение не отправляет сообщения получателям.

После `/start` бот показывает текст согласия и кнопку подтверждения. Подтверждение добавляет контакт по числовому Telegram ID, фиксирует источник, бота, номер события, время, текст и версию согласия. Email-разрешения и глобальный статус контакта не меняются. `/stop`, `/unsubscribe` и блокировка бота отзывают подписку. Старые кнопки после отписки или переподключения недействительны; нужна новая команда `/start`.

Кнопка «Создать рассылку» открывает мастер с Telegram и списком активных подписчиков текущего бота. Доступны текст, персонализация, PDF и существующий запуск по расписанию. Для Telegram не нужно заполнять email-макет. Отправленные ранее сообщения не скрывают подписчика из новой Telegram-кампании; действуют существующие проверки нагрузки и оснований. Сервер проверяет принадлежность подписки боту перед запуском, а актуальное подключение и отказ — перед каждой передачей сообщения. Очередь сохраняет принятые, отклонённые и неопределённые результаты; сетевые ошибки автоматически не повторяются.

## Серверная настройка

- `TELEGRAM_CREDENTIAL_KEY`: секрет, 64 шестнадцатеричных символа, случайные 32 байта. AES-GCM, отдельный IV на запись и привязка шифротекста к рабочему пространству и ID бота. Нельзя менять ключ без повторного подключения ботов или миграции шифротекста.
- `TELEGRAM_WEBHOOK_ORIGIN`: доверенный публичный HTTPS origin приложения, без пути и завершающего слеша. Не определяется по клиентскому заголовку Host.
- Миграция `0019_tidy_rockslide.sql` создаёт только таблицы подключения, подписчиков и обработанных событий. В runtime-init дублирующего DDL нет.

Токен не возвращается из API, не попадает в public_config, localStorage или sessionStorage. Публичные параметры содержат только источник credentials, ID и username бота. Webhook проверяет SHA-256 секрета из заголовка Telegram; тело ограничено 64 КБ. Записи подписки, контакта и доказательства обновляются одной D1 batch-транзакцией. Повторные update_id и устаревшие события не меняют согласия. Чужой webhook не перехватывается. Одновременно подключён один бот на рабочее пространство; смена бота требует отключения и не переносит его подписчиков.

Старые серверные `TELEGRAM_BOT_TOKEN` / `_2` остаются совместимы с ранее настроенной доставкой. Новые подключения выполняются через форму. Проверки с замоканным Telegram и настоящим SQLite находятся в `tests/telegram-connection.test.mjs`; реальные сообщения тесты не отправляют. Финальную проверку живого webhook владелец проводит своей подпиской после подключения собственного бота.
