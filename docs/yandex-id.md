# Вход через Яндекс ID и личные пространства

Новая регистрация без приглашения создаёт отдельное пространство. Его владелец получает роль администратора, три стартовых макета и отключённые каналы отправки. Контакты, загруженные файлы, рассылки и реквизиты существующей команды не копируются. Приглашение присоединяет пользователя только к пространству автора приглашения.

Приложение Яндекс ID создаётся на https://oauth.yandex.ru/ для авторизации пользователей. Название: «Поток», иконка: `public/potok-logo.png`. Укажите оба Redirect URI:

- https://mailflow-outreach.isakovegor820.chatgpt.site/api/auth/yandex/callback
- https://potok.slava-hunter.ru/api/auth/yandex/callback

Права: `login:info` (имя) и `login:email` (адрес почты). После создания добавьте Client ID как переменную `YANDEX_CLIENT_ID` через Sites Environment Variables и опубликуйте сохранённую версию. Client Secret не нужен: используется PKCE S256. Без Client ID интерфейс скрывает кнопку и не предлагает неработающий вход.

OAuth проходит через сервер. Одноразовое состояние привязано к браузерной HttpOnly cookie и действует 10 минут. Код обменивается на токен с PKCE, затем проверяется Client ID профиля. Токен Яндекса не сохраняется. Уникальный идентификатор пользователя связывается с аккаунтом; совпадение email не объединяет аккаунты. Привязка к существующему аккаунту доступна в настройках и требует ту же активную сессию на старте и при возврате.

Рабочее пространство определяется серверной сессией в request-local AsyncLocalStorage. Параметры клиента не выбирают пространство. Системный планировщик обрабатывает очереди в контексте их владельца. Серверные секреты каналов прежней команды доступны только `workspace-main`; личные клиенты их не наследуют. Генерация материалов использует общие сервисные настройки ИИ. PDF из хранилища требуют сессию своего пространства; изображения остаются доступны по уникальной ссылке для отображения в отправленных письмах.

Основные тесты: `tests/private-workspace-yandex.test.mjs`, `tests/team-access.test.mjs`, `tests/database-initialization.test.mjs`, `tests/communication-controls.test.mjs`. Локальная проверка на двух аккаунтах дополнительно подтвердила изоляцию 10 API-разделов и отклонение чужих изменений контактов, чтения и удаления шаблонов и презентаций.

На момент подготовки к публикации: 311 тестов, 297 проходят. Все 14 оставшихся ошибок воспроизведены на исходной версии 389589a без изменений этой задачи; список совпадает. Новые тесты регистрации и изоляции проходят. TypeScript, ESLint изменённых файлов и production build проходят. Лендинг, вход и регистрация проверены на ширине 1440, 390 и 320 px.
